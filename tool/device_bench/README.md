# device_bench: dianoia on a phone

A Flutter app that runs dianoia on an iPhone or an Android phone, on the
CPU kernels and on the GPU (Metal or Vulkan). It depends on the package by
path, so the kernels reach the app through the package's build hook, the
same way they reach any Flutter app: there is no plugin and no platform
build file for them. It starts its benchmark at launch, so it can run
without touching the phone, and writes `bench/latest.json` plus
teacher-forced dumps under `out/` for the Mac-side checks.

`run_ios.sh` and `run_android.sh` do the whole round trip: build, install,
copy the model bundle (once), launch, wait, copy the results back and
compare them with the same runs on this Mac. They need dart-llm-lab checked
out next to this repository (`LAB=` to point elsewhere), which holds the
models, the transformers reference runs and the Python comparison tools.

```bash
WEIGHTS=q4 tool/device_bench/run_ios.sh       # the first connected iPhone
tool/device_bench/run_android.sh              # QAD Q4, the first adb device
```

The app keeps the bundle identifiers of the lab's bench app
(`com.noguwo.dartllmlab.lfm3Bench`, `com.noguwo.dartllmlab.lfm3_bench`), so
it replaces that app on a phone and reuses the model bundles already copied
there.

Android builds go through Gradle directly (`android/gradlew`, generated by
Flutter and not committed), with any JDK 17+ in `JAVA_HOME`; Android Studio
is not needed.

# LFM3-VL-2B real-checkpoint validation

On 2026-11-01, the actual LFM3-VL-2B checkpoint completed the RGB-to-answer
pipeline with matching generated tokens in three synthetic image cases. Both
CPU float32 language inference and Q8/Metal language inference passed the checks.
The vision encoder/projector runs on the CPU in both dianoia configurations.

Implementation commit: `e6ecdb695c2c98048fdf741ac6ab42486644790e`.

## Checkpoint and environment

- Model: [LiquidAI/LFM3-VL-2B](https://huggingface.co/LiquidAI/LFM3-VL-2B/tree/ba44bd51db20a2753f28c273a1571ccaa210d954).
- Revision: `ba44bd51db20a2753f28c273a1571ccaa210d954`.
- Safetensors size: 3,836,417,920 bytes.
- SHA-256: `a9bb8b1c159c9d6c3007bc1c7ad8018b599f759d97da2701714e37426283e131`,
  verified against the upstream LFS metadata before recording results.
- Apple M2 Max, 64 GB RAM, macOS arm64; Dart 3.13.5 AOT.
- PyTorch 2.15.0, Transformers 5.21.0, torchvision 0.29.2. The upstream
  checkpoint's actual processor and model executed locally in CPU float32,
  using eager attention and four PyTorch threads.
- Greedy decoding, thinking disabled, eight-token generation limit, 256-token
  context in dianoia. All images are 256x256 RGB, resulting in a 16x16 patch
  grid and 64 language image tokens. CPU and Metal runs use the same imported
  VL language weights; Q8 is generated by dianoia, not a QAD GGUF checkpoint.

## Results

| Input | Question | Upstream | dianoia CPU F32 | dianoia Q8/Metal | CPU prefill logits max error | Q8/Metal prefill logits max error |
|---|---|---|---|---|---:|---:|
| Solid red | Main color? | Red | Red | Red | 0.0000775 | 0.4387 |
| Solid blue | Main color? | Blue | Blue | Blue | 0.0000749 | 0.2976 |
| Left red, right blue | Color on the left? | Red | Red | Red | 0.0000648 | 0.2383 |

Prompt token IDs, generated token IDs and normalized patch bytes match exactly
in every run. Encoder/projector stages and both prefill and decode logits are
checked element by element. The maximum projector difference across the cases
is approximately 5.1e-6. All six comparisons pass.

Float32 comparisons use `abs(error) <= 0.002 + 0.0002 * abs(reference)`.
Q8/Metal uses that same bound for the vision stages and an absolute logit bound
of 0.5 (zero relative tolerance) for the quantized language model. Quantization
changes logits; these checks also independently require exact generated IDs.
Bounds apply to this smoke check and are not general accuracy thresholds.

The [machine-readable results](validation/lfm3-vl-2026-11-01.json) include image
hashes, complete prompts, generated IDs, error metrics and single-run timings.
Raw tensors, images, downloaded implementation files, weights and caches remain
under ignored `build/vl-validation/` and are not committed.

This establishes the complete connection for these three known color/spatial
cases. This initial run did not cover natural photographs, OCR, Japanese answers,
multi-image reasoning or phone latency/quality. A subsequent
[natural-image/OCR/Japanese follow-up](lfm3_vl_extended_validation_2026-11-01.md)
adds one photograph and two OCR cards. Single-run timings are diagnostic
observations, not a sustained performance benchmark.

## Reproduction

Use a separate Python environment with `tool/requirements-vision-validation.txt`.
Download the pinned checkpoint and all its Python/config/tokenizer files into
`build/vl-validation/model`. Keep the downloaded weights outside version control.
Create an RGB test image, for example:

```python
from PIL import Image
Image.new('RGB', (256, 256), 'red').save('build/vl-validation/red.png')
# For the spatial test, paste blue over (128, 0, 256, 256).
```

Run from the repository root, with a new output directory for each command:

```sh
dart build cli -o build/vl-validation/cli
CLI=build/vl-validation/cli/bundle/bin/dianoia
VL=build/vl-validation/model
BACKBONE=build/vl-validation/backbone

# Generates source/output cache fingerprints as vl_backbone.json.
"$CLI" import-vl-backbone --model="$VL" --out="$BACKBONE"

# Use a local writable HF cache when running in a sandbox.
HF_HOME="$PWD/build/vl-validation/hf-cache" python tool/vision_reference.py \
  --model="$VL" --image=build/vl-validation/red.png \
  --prompt='What is the main color? Answer with one color word.' \
  --out=build/vl-validation/reference-red --max-new=8

"$CLI" vision-run --model="$VL" --backbone="$BACKBONE" \
  --rgb=build/vl-validation/reference-red/input.rgb --height=256 --width=256 \
  --prompt='What is the main color? Answer with one color word.' \
  --out=build/vl-validation/dianoia-red-f32 --weights=f32 \
  --max-new=8 --max-seq=256

python tool/vision_compare.py --reference=build/vl-validation/reference-red \
  --actual=build/vl-validation/dianoia-red-f32 \
  --out=build/vl-validation/red-f32-comparison.json
```

For Q8/Metal, use a new output directory and `--weights=q8 --gpu` in
`vision-run`. Compare with `--logits-atol=0.5 --logits-rtol=0`; vision bounds
stay unchanged. The first Q8 run creates a language-weight cache. Model weights,
the imported full backbone and that cache together require about 9 GB of disk;
reference CPU inference also widens the checkpoint to float32 in memory.

`vision-run` requires a fresh import with `vl_backbone.json`. Its cache
fingerprints detect a changed checkpoint header, size or config; they are not
cryptographic payload verification. Check the full checkpoint SHA-256 separately,
as in this recorded run. A result is complete only after `meta.json` is written;
`vision_compare.py` exits nonzero for failed checks or incomplete evidence.
